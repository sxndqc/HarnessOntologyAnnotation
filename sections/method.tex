\subsection{Overview}
\label{sec:overview}

\sys turns an annotation guideline and a few annotated sentences into an annotator, without training any model. Nothing in it is specific to a scheme: a benchmark supplies the guideline, the output format, a parser for that format, and an evaluator; the rest is shared (Figure~\ref{fig:overview}).

\paragraph{Annotator.} An annotator is a harness $H=(S,T,G,R)$ run by language models: \emph{skills} $S$, the instructions of each model step; \emph{tools} $T$, typed Python functions a step may call; a \emph{chain} $G$, the order of the steps and the model that runs each; and \emph{rule steps} $R$, code that rewrites an annotation without a model. A document is annotated sentence by sentence. Each step sees the document header, the five preceding sentences with their final annotations (a registry of the document so far), the sentence, the current annotation and the open findings. A \emph{rewrite} step writes the complete annotation of the sentence, a \emph{check} step returns findings (a problem and its fix) for the next rewrite step, a rule step is code. The final annotation is the last one that parses. Every step receives the same fixed output format; nothing else is fixed.

\paragraph{Seed.} The builder model reads the guideline and writes the seed harness $H_0$: three steps, \skill{generate} (writes the annotation), \skill{critique} (lists problems) and \skill{finalize} (rewrites the annotation with the findings), each a checklist of about 8{,}000 characters (the builder is asked for at most 8{,}000). It sees no annotated data and the seed has no tools.

\paragraph{Recursive self-improvement.} Training data come as groups of five consecutive sentences of one document. Round $n$ turns $H_{n-1}$ into $H_n$ with group $n$ (\S\ref{sec:rsi}): annotate the group, score it with a fine-grained judge, let the builder summarize the problems, reflect on their causes and propose operations on skills, steps and tools, admit the operations that pass machine checks, and annotate the group again. Each $H_n$ is also tested on held-out documents, which the builder never sees.

\subsection{Two benchmarks}
\label{sec:benchmarks}

\paragraph{UMR.} A UMR annotation of a sentence \citep{vangysel2021designing,bonn2024building} is a rooted graph in PENMAN notation whose nodes are concepts: events with PropBank-style senses \citep{palmer2005propbank} or language-specific lemmas, entities, named-entity types, and abstract rolesets such as \texttt{have-org-role-92}; edges are participant roles (\texttt{:ARG0}, \ldots) and non-participant roles (\texttt{:temporal}, \texttt{:manner}, \ldots); attributes give aspect, polarity, mode, and the person and number of referring expressions. Each node is aligned to the words it comes from. A document-level graph per sentence adds temporal relations between events and times, modal relations between conceivers and events (who asserts what with which strength), and coreference with earlier sentences. The guideline \citep{vangysel2021designing} has 365{,}742 characters.

\paragraph{TimeML.} A TimeML annotation \citep{pustejovsky2003timeml}, following the TimeML 1.2.1 guidelines \citep{sauri2006timeml} as in TimeBank~1.2 \citep{pustejovsky2006timebank} and TempEval-3 \citep{uzzaman2013semeval}, marks time expressions (\texttt{TIMEX3}, with a type and a normalized value such as \texttt{2013-W11}), events (\texttt{EVENT}, with a class and the tense, aspect, polarity and modality of its instance), and temporal links (\texttt{TLINK}) of thirteen relation types between events, times and the document creation time, across sentences. The guideline has 115{,}146 characters. An annotation of a sentence is the sentence with inline tags followed by its TLINK lines.

\paragraph{Judges.} The builder needs to know which part of the scheme an error belongs to. For UMR we use umrjudge: AnCast++ \citep{sun2024anchor,sun2025ancastpp} aligns predicted and gold nodes, and 25 checks in 11 groups compare the aligned graphs (nodes, senses, attributes, arguments, role labels, names, reentrancy, and the document-level temporal, modal and coreference relations; Appendix~\ref{app:judge}). For TimeML we built timemljudge on the same design from earlier evaluations: TempEval-3's extent and attribute measures for times and events \citep{uzzaman2013semeval}, and the TempEval-2 split of temporal links by what they connect \citep{verhagen2010semeval}, event--time in one sentence or across sentences, event--document time, event--event in one sentence or across, and time--time, each scored for which pairs are linked and for the relation of the pairs linked on both sides. Both judges return \emph{units}, each with a verdict (correct, wrong, missing, extra), the sentence, and the gold and predicted elements.

\subsection{The harness and its improvement}
\label{sec:rsi}

\paragraph{Representation.} A harness version is a directory of plain files: \texttt{harness.yaml} (the chain: each step's name, kind, model and tools), one Markdown skill per model step, one Python module per tool, one per rule step. A version is never changed after it is written; round $n$ copies $H_{n-1}$ and edits the copy. A configuration names two models: the generator G runs \skill{generate} and \skill{finalize}, the critic C runs \skill{critique}; a step the builder adds names which of the two runs it.

\paragraph{Resources.} The annotating steps see only their input. Tools may read resource files through one module; the builder is told what files exist (for UMR: the Chinese and English PropBank frame files, the UMR lists of abstract rolesets, relations and attribute values, and the guideline; for TimeML: the guideline) and may look into them while it reflects. It is not told what to build: in the seed there are no tools, and a PropBank lookup has to be invented.

\paragraph{One round.} (1) \emph{Annotate}: $H_{n-1}$ annotates the five sentences of group $n$; the sentences before the group are given with their gold annotations as context. The trace keeps every step's output and findings. (2) \emph{Judge}: the group is scored and the judge lists the units that are not correct. (3) \emph{Reflect}: one builder call receives the output format, the harness (chain, all skills with their sizes, all tools), the resource manifest, the previous rounds' changes and training scores (never a test score), and for each sentence its gold annotation, every step's output and its incorrect units. It returns \emph{problems} (error patterns with evidence and the step to fix), a \emph{reflection} (why they happen and what to change), \emph{operations}, and \emph{suggestions} it cannot implement. The builder can list and read resource files and search the guideline during the call. (4) \emph{Admit}: operations are applied in order to a copy of $H_{n-1}$ if they pass machine checks. (5) \emph{Re-annotate} the group with $H_n$, and test $H_n$ on held-out documents.

\paragraph{Operations.} \texttt{edit\_skill} modifies, inserts or deletes text at an anchor that must occur exactly once; \texttt{rewrite\_skill} replaces a skill, to consolidate it; \texttt{add\_step} inserts a check, rewrite or rule step after an existing step, \texttt{delete\_step} removes one (at most five model steps); \texttt{add\_tool}, \texttt{replace\_tool} and \texttt{delete\_tool} manage tools, and \texttt{set\_step\_tools} decides which steps may call which tool.

\paragraph{Admission.} Every operation is checked by machine; there is no reviewer model, so that tools and steps are not blocked by a second opinion. No text may copy eight consecutive characters (Chinese) or six consecutive words (English) of a test sentence. A skill may not grow beyond 10{,}000 characters; an edit that would is rejected, and the builder is told to consolidate with \texttt{rewrite\_skill}. This keeps the harness compact as rounds accumulate. A tool or rule must import only whitelisted modules (the resource module included), use no file, evaluation or reflection primitives, define one public function with type annotations and a docstring, and pass at least three tests of its own in a separate process; a tool that fails is returned once to the builder with the error. A new step must follow an existing one, and the first step must stay a rewrite step.
