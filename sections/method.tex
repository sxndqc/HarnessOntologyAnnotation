\subsection{Harness structure}
\label{sec:overview}

An annotator is a harness $H=(S,T,G,R)$ run by language models: \emph{skills} $S$ provide step instructions, \emph{tools} $T$ are callable Python functions, a \emph{chain} $G$ specifies step order and model assignments, and \emph{rule steps} $R$ rewrite annotations through code.

\paragraph{Execution} Each step receives the input text, the current annotation, and unresolved findings from earlier steps. A \emph{rewrite} step produces a complete annotation; a \emph{check} step identifies problems and proposes fixes for the next rewrite; a rule step runs code. All steps share the output format; their instructions are learned.

\paragraph{Resources} Model steps access resource files through tools. Tools use a shared module to read resources such as lexicons, label lists, and the guideline. The tools themselves are written by the builder as the harness evolves.

\subsection{Initialization}
\label{sec:seed}

The builder LLM reads the guideline and writes a seed harness $H_0$ with three steps: \skill{generate} produces an annotation, \skill{critique} lists problems, and \skill{finalize} revises the annotation using those findings. Each step has a checklist of at most 8{,}000 characters. The builder sees no training examples, and the seed has no tools. A generator G runs \skill{generate} and \skill{finalize}, and a critic C runs \skill{critique}; any model step added later is assigned to one of these roles.

\subsection{Recursive self-improvement}
\label{sec:rsi}

Round $n$ turns $H_{n-1}$ into $H_n$ using the next training group (Figure~\ref{fig:overview}). Changes are made to a copy of the harness, preserving earlier versions.

\paragraph{Annotation and feedback} $H_{n-1}$ annotates a group of cases. The trace records each step's output and findings. A fine-grained judge aligns predictions with gold and checks individual parts of the annotation scheme, such as concepts, argument roles, attributes, and links. It returns units containing a verdict and the gold and predicted elements, together with the sentence they belong to. Incorrect units identify which decisions need improvement. The judges used in our experiments are described in \S\ref{sec:evaluation}.

\paragraph{Reflection} In one call, the builder receives the current harness, the resource manifest, the changes and training scores from earlier rounds, and the training group's gold annotations, step outputs, and incorrect units. It may inspect resource files and search the guideline. It returns error patterns, their causes, proposed operations, and suggestions outside the available operations. Suggestions are recorded but not applied.

The builder can edit or rewrite skills, add or remove model and rule steps, create, revise, or remove tools, and change which tools a step may call. Operations are applied in order when they pass machine checks. Local text edits require a unique anchor; full rewrites consolidate instructions. Skills may contain at most 10{,}000 characters, and the chain at most five model steps. New steps follow an existing step, and the first step remains a rewrite.

Added text may not copy spans of test sentences (eight characters in scripts without word spaces, six words otherwise). Tools and rules must use whitelisted imports, avoid direct file access, code evaluation, and introspection, define a documented function with type annotations, and pass at least three tests in a separate process. Failed code is returned to the builder for one repair attempt. Machine checks determine admission, without a reviewer model.

\paragraph{Evaluation and continuation} The resulting $H_n$ re-annotates the training group and is evaluated on held-out texts. It then becomes the starting harness for round $n+1$. The builder never receives test texts or test scores.
