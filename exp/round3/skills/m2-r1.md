- **Temporal direction:** `(A :before B)` means B is before A; `(A :after B)` means B is after A. The relation describes the child relative to the parent. For a past event write `(document-creation-time :before e)`, never `(DCT :after e)` or `(e :before DCT)`. For "X then Y" write `(X :before Y)` only if X is the parent and Y is earlier; usually write `(X :after Y)` or `(Y :before X)`. Check every chain (cause→result, plan→planned, request→requested, purpose→main event, "after/before" clauses). Give every event and every date a temporal parent; link a date to its event with `(date :contained event)`.
- **PropBank frames:** Look up every predicate and use only the arguments that the chosen roleset has. Do not invent ARG1/ARG2/ARG3/ARG4 by analogy with English. One-argument predicates (adjectives, 身亡, 不同, 有限, 来自, 位于, 邻近, 行之有效) take ARG0 for the described entity. Choose the sense whose arguments fit (e.g. 追溯-02, 加入-02, 限制-02, 运-02, 居-02). Use the original word, not a near-synonym (设有, 迁至, 购自, 常用, 惨死, 印有, 写道, 长达, 改为). If the word is not in PropBank, write 词-00, never an invented -01. When core arguments cannot express a role, use a non-core role: :place, :source, :goal, :instrument, :medium, :manner, :affectee, :companion, :end-state.
- **Copulas and abstract predicates:** Do not make nodes for 是/为. Use identity-91 for equations and apposition, have-org-role-92 (ARG1 person, ARG2 organization, ARG3 title), have-rel-role-92 (ARG1 person, ARG2 relative, ARG3 role), have-degree-91 for 最X, exist-91 for existentials, but-91/contrast-91 (:ARG1 :ARG2) for 但/而/则, have-reason-91 for reason–result. Never cause-01, contrast-01, have-org-role-91, or have-rel-role-91. Prefer a verb with its own PropBank entry (位于-01) over have-place-91.
- **Role names:** use :possessor (not :poss), :place (not :location), :companion (not :accompanier), :part-of when the part is the parent and :part when the whole is the parent, and (member :subset-of set) with the member first. Use :medium for a language or channel, :manner for adverbial modifiers (连续, 普遍, 以…名义), :instrument for tools, and :mod for 亦/也/还/又/均/已经/同样/仅/各自/更. Never :degree for adverbs that modify events; reserve it for degree adverbs that modify qualities (非常, 最).
- **Do not drop words:** keep classifiers as :unit with a digit :quant (一座 → :quant 1 :unit 座), the demonstrative 该/此 as :mod, 开始/继续 as predicates, 等 as a list member or :mod, 原, 随即, 其中, 之 as pronouns. Light verbs (进行, 得到) can be dropped in favor of the real predicate. Modal words (可, 必须, 可能, 无法) get no node; they only set modal strength.
- **Named entities:** Proper names (people, places, organizations, languages, roads, stations, buildings) get an English type from the type table (organization, government-organization, company, country, city, province, local-region, road, station, building, language, person) plus :name with each word as its own quoted :opN. Never use a Chinese common noun as the type (电视台, 地区, 医院, 街, 组织). Do not merge two places or a place and an organization into one name. Do not use a bare unquoted string as a value. Write clock times as quoted strings or as a concept node; do not split "7:30" into separate roles.
- **Aspect:** Habitual or generic repeated processes are `habitual`. Progressive 正在/着 is `activity`. Completed past events are `performance`. Do not mark process verbs as `state`. Do not put an aspect on non-event entity nouns.
- **Modal structure:** Every event needs a modal parent. Negated events (:polarity -) are `full-negative`, never full-affirmative. The complement of 计划, 申请, 要求, 允许, 需要, 呼吁, 无意 or a purpose clause hangs under that predicate with `unspecified` (or the strength the predicate implies); the author does not assert it. Reported speech, thought or a quotation: author → speaker/reporting event → content. 可/能 gives neutral-affirmative, 应该/必须 gives partial-affirmative.
- **Coreference:** Link every repeated mention to the nearest earlier one, with the earlier mention first: (earlier :same-entity later). Do this for proper names, places, 该X, 此X, and repeated events (:same-event). Use :subset-of for part/member relations. Do not link a node to itself, name nodes, entities to events, different instances (a second application, a different quantity), or a node that is only a subset. Within one sentence, reuse the same variable (re-entrancy); do not add a :coref triple or duplicate nodes.
- **Graph hygiene:** Each event gets one temporal parent and a sensible modal parent. Use only UMR roles (no :alias, :refer-to, :domain, :exception, :compared-to, :modifier). Use umr-unknown for questions. Do not leave a sentence empty.
