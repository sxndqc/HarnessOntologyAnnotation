- **Temporal direction:** `(A :before B)` means B is before A; `(A :after B)` means B is after A. For a past event write `(document-creation-time :before e)`. A date is a parent: `(date :contained e)` only if the event is strictly inside it; for a plain "in year X" event use `(date :overlap e)`. Do not put `document-creation-time :before` on a date that already has a parent, and do not give a date a second DCT link. For present states and habitual statements use `(document-creation-time :overlap e)`. Events in the same situation (state + described event, 不同 + the thing compared, 限于 + the broadcast it limits, 申请 + its content) chain with `:overlap` to each other rather than to DCT. Plans (计划) are `:overlap`/earlier than nothing: the planned event hangs under the plan with modal `unspecified`, and temporal `:after` the plan only when it is clearly later.
- **PropBank frames:** Look up every predicate; use only the roles of the chosen roleset. Use the original word, not a near-synonym or a longer form (批 not 批予/批准, 售 not 售予, 放上, 调往, 达到 for 达不到 + polarity -, 现存, 发, 撰, 致力于). Write the -NN suffix on every verb concept when it exists in PropBank (空袭-01, 救援-01, 行动-01, 裁决-01, 简称-01, 收费-01, 武装-01, 无意-01, 起步-01, 常用-01, 惨死-01, 查访-01); only drop the number when the word is truly absent. Prefer the sense whose args fit (限于-02, 要求-01 vs -02 by meaning). Core roles must match the roleset: the doer is ARG0 and the affected thing ARG1; check the label order, do not swap ARG0/ARG1 for intransitives by analogy with English.
- **Abstract predicates:** Never make nodes for 是/为. Use identity-91, have-org-role-92, have-rel-role-92, have-degree-91, exist-91, but-91/contrast-91 (not "contrast"), and-contrast, have-reason-91 / have-cause-91 as the guideline names them (not "have-reason", not 致使). For 致使/令 causatives use have-cause-91 with ARG1 the cause event, ARG2 the result. For "include/例如/其中/等" use include-91 / have-example-91. Give each such abstract node a modal `author :full-affirmative`, and give 旗下/属/位于-type states an aspect `state`.
- **Entity types:** Use the most specific type: company for businesses and TV companies (not organization), armed-organization for militaries, international-organization for UN-type bodies, government-organization for government bodies, individual-person for a named person (not person), country-region for China/Taiwan/regions, nationality for nationality, broadcast-program for named programs, geographical-coordinate-entity. Use an English concept for a Chinese common noun that has one (television-station is NOT the type: use 台/频道/电视台 as the Chinese word only when no English type exists; follow the type table). Do not translate 后/前 into after/before concepts; use them as :temporal/:mod on the event or as a temporal-quantity.
- **Names:** Split names into the words as written; do not include type suffixes (市, 县, 镇, 村, 区, 公司) inside the name unless the guideline says the suffix is part of the name; keep org names to the name itself (贝尔, not 贝尔 公司). Do not name common nouns (牌坊, 政府 alone, 北洋 as modifier). Dynasty/era words (明代, 清代) are not names: use a date-entity or :mod. Book/program titles in 《》 keep the 《》 tokens in the name. Do not add abbreviations in parentheses (UNRWA, OCHA, TVBS) to the name.
- **Numbers and units:** A counted noun gets `:quant N` and `:unit classifier` (条, 套, 座, 间, 项, 种, 个, 辆, 名, 批, 次, 小时, 公吨, 米). Do not write the classifier as an attribute; do not drop the unit. Numerals, clock times and coordinates are written as plain values with no extra attributes; do not make extra attribute entries from them. Percent/ordinal: use ordinal-entity with :value.
- **Roles:** :mod for modifiers (收费, 地区性, 主要, 少数, 各, 同, 其它, 曾, 亦, 又, 首次); :place for locations only where the thing is located; :part / :part-of for parts (南部, 港口, 上面, 其下); :medium for language, signal, channel, and transmission means (讯号, 语言); :manner for 立刻, 一致, 精确, 直接, 一并, 误; :purpose for purpose clauses; :cause for cause clauses; :temporal for time words (后, 前, 内, 现在, 事先). Possessors stay :possessor. Modal adverbs like 曾 are :mod, never concepts.
- **Aspect:** Habitual = repeated or regular (every day, 播放 schedules, 程序 descriptions, general facts about practice). Completed past event = performance. Ongoing past state = state. Process = ongoing unbounded events in the past or present; endeavor = attempted/planned goal-directed activity (计划, 申请, 转型). Every event has an aspect: include 状态 (state) for descriptive/stative predicates such as 属, 位于, 有, 存在, 不同, 来自.
- **Modal structure:** Every event gets a modal parent; do not leave events without one. Asserted facts: `author :full-affirmative`. Complements of 计划/申请/要求/允许/希望/无意 hang under that predicate with `unspecified` (or a strength implied). Speech/report: author → reporter (形容, 指, 认为, 表示) → content, and the reporting event is itself full-affirmative under the author. Negated events: full-negative. Do not mark an event as neutral-affirmative unless 可/能/会 is expressed with a clear possibility meaning; 会 as future habitual in a reported statement stays as stated.
- **Coreference:** Chain every repeated entity and event to its previous mention across sentences (same company across sentences, repeated 频道, 牌照, 雨势, 政府, 申请, 空袭): `(earlier :same-entity later)`. Link a pronoun-like 该X/此X/其 to its antecedent. Do not link a mention to a different instance or to a part.
- **Graph hygiene:** Use only UMR roles. No empty sentences. Reuse variables within a sentence instead of duplicating nodes. Implicit arguments (零指代) are written as implicit-argument when needed for a core role; do not drop a participant that fills an ARG of an event just because it is not written.
