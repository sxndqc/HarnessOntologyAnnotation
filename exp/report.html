要点

  • 样本很小：只有 3 篇测试文件（中文 zh-0028、zh-0032，共 18 句；英文 en-0008，9 句），每个条件只跑一次。下面几分以内的差别都在噪声范围里；中文 15 篇、英文 5 篇的全量还没跑。
  • 所有 LLM 设置都明显高于两支参赛队伍：这三篇上 juːmæʧ 中文 41.8–50.9（最低的是 Claude Code 的 s1-full），参赛队伍 32.0、32.2；英文 44.6–59.2，参赛队伍 41.0、35.6。
  • 五个条件之间总分差别很小（Claude API 中文 48.1–50.0）；资源的作用在分项里：PropBank 让谓词义项和核心角色标签提高 9–17 分，gold 例子让共指和人称/数提高，guideline 搜索让角色标签提高约 10 分；几乎所有资源都让文档级模态关系略降。
  • Claude 三种方法（API、Claude Code、claude.ai chat）总分基本一样；Claude Code 的 s1-full 偏低（41.8）。
  • GPT（gpt-6.1-sol）和 Claude 总分接近：前五个条件和 a1，中文都是 Claude 略高（差 0.6–4.3）；三个工具都给时（s3-all、a2）GPT 更高。英文各有高低，GPT 拿到完整 guideline（full、+search）或三个工具后高于 Claude。GPT 调用工具的次数是 Claude 的几倍到几十倍；只给一个工具时，多查并没有让分数更高。
  • 一句句跑：只给 PropBank 时（a1）和整篇一次标相差 2 分以内；三个工具都给、一句句跑（a2）是中文目前最好的设置（Claude 50.8、GPT 51.6，Smatch 60.9、61.7），两个模型这时都查得最多。三个工具都给但整篇一次标（s3-all）时，GPT 中文 50.1、英文 56.9，Claude 中文 48.8、英文 51.8（Claude 只查了 2–3 次）。
  • 全量估算（中文 15 篇 + 英文 5 篇，这 8 个条件全跑）：Claude Opus 5.5 约 $230，gpt-6.1-sol 约 $70；最贵的是一句句跑的两个条件。按 3 篇外推，误差大约 ±50%。
  • 对齐不让模型写，由程序自动生成：gold 的图配自动对齐，中文 juːmæʧ 87.4、英文 65.9（英文 gold 自己的对齐有不少错位）。自动对齐比模型自己写的对齐还好（同样的图高 3–9 分）。

局限和下一步

  • 3 篇文件、每个条件跑一次：没有量过同一条件重复跑的波动，也没有置信区间。
  • effort 都是 medium；模型查资源的次数（尤其 Claude）很少，资源条件的对照因此偏弱。
  • 英文的自动对齐上限只有 65.9（中文 87.4），英文的 juːmæʧ 会因此偏低；Smatch 不受对齐影响。
  • 下一步建议：中文 15 篇全量（API 和 Claude Code），同一条件重复 2–3 次量波动，按文件 bootstrap 求置信区间，以及让模型真正去查资源（调高 effort 或在 prompt 里规定每句都查）。
