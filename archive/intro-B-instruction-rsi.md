# 会用工具、会进化工具的标注 Instruction

（第二篇：Instruction + RSI，在 ACL 2026 那篇的基础上扩展，加入工具使用、工具和 skill 的自我进化，用于复杂标注。标题待定。）

## Introduction

为执行或分析特定任务，人们常常需要设计专用的 ontology，并按 guideline 标注数据。传统做法依赖大量人工，起步阶段的数据生产既慢又贵。【引用】复杂的语义标注尤其如此。以 UMR 为例，一句话要写出完整的语义图，包括概念、义项、论元、aspect 和命名实体；整篇文档还要再加一层时间、模态和共指关系。标注员需要长时间培训，一篇文档往往要标几个小时。【引用：UMR 标注成本】

标注包含两件事：识别数据里的结构，以及把结构映射到 ontology 的标签和规范上。大模型在预训练中已经见过大量语言，对"谁做了什么、什么时候、有多确定"这类结构有相当好的把握，这一半可以交给模型。剩下的是 ontology 本身的规范，例如 PropBank 的义项和论元框架、UMR 的属性取值、中文的特殊约定。这是外部知识，模型不可能天生知道。

【ACL 2026 那篇：一两句话概括它做了什么。例如：把 guideline 写成给模型的 instruction，让模型对照 gold 自动改写 instruction，在 xxx 任务上接近或超过人工撰写的 guideline。】这条路线的核心思想是：**面向模型的 guideline 不必模仿面向人的 guideline。** 人需要流程和大量例子，是因为人要从零学会这套表示，一次只能顾及少数几件事；模型已经具备语言和语义知识，能一次处理整句，缺的只是"目标表示长什么样"，以及"这套 ontology 在哪些地方和它的直觉不一致"。

但把这条路线用到 UMR 这样的复杂标注上，只改写 instruction 还不够，原因有二。第一，外部知识的量太大，写不进 instruction：PropBank 有上万个框架，模型不可能靠记忆选对义项和论元编号。第二，有些错误是机械的，例如属性取值写错、角色名用了 AMR 的写法、事件缺了 aspect，用一小段程序检查远比用一段文字提醒可靠。也就是说，模型不仅需要更好的说明，还需要**工具**；而且最需要哪些工具，事先未必知道，应当和说明一样，从错误中学出来。

我们在 ACL 2026 那篇的基础上做了三点扩展：

1. **工具使用**：每个 skill 都可以调用通用工具，包括查 PropBank 框架的 `propbank_lookup` 和取例子的 `get_example`。外部知识按需查询，不再塞进 instruction。
2. **工具和 skill 的自我进化**：反思（RSI）不仅能改写说明，还能提议新的工具（一个纯 Python 函数，所有 skill 都能调用），或者在链上加一个新的 skill。为了防止进化失控，每个提议都要通过两道审核：先是机器检查，包括 import 白名单、AST 级别禁止文件和网络访问、自带测试在隔离进程里全部通过，以及和训练、测试文档的文本没有 8 字以上的重合；再是一个审核 agent 的严格评估，看问题是否反复出现、改现有 skill 能否解决、职责是否单一、是否值得多一次调用。
3. **复杂标注**：链条很短，每句 3 次模型调用。generate 只凭说明（没有例子）直接写整张句子图；critique 按评测的类别（节点、义项、属性、论元、角色、命名实体、重入）逐类检查常见错误；接着用规则修好图的合法性；最后 document 一次写出文档级的时间、模态和共指关系。critique 的"常见错误"清单由 RSI 从 gold 中逐条积累。

在中文 UMR 上，这种方法用很低的成本取得了比模仿人类流程更好的效果。【待核：以下对比的训练文档相同，但轮数不同】在都只见过 0001～0004 的条件下，它在 0005 上达到 58.5 句子 F，而按人类标注流程逐步决定的 skill orchestration（umr-tree）为 55.7；每句成本约 $0.08，对方约 $0.7。逐步消融还显示，提升主要来自 instruction 本身：critique 只带来 0.5～2 F，generate 的说明经过 RSI 从 43.5 提高到 75.7（0001 上的训练过程）。另一个设置用了五个分别检查概念、论元、属性、实体、重入的步骤（umr-refine），它们在训练文档上能贡献 6～9 F，在测试文档上却接近 0 甚至为负。这说明多加的检查步骤学到的多半只是对训练文档有效的修补。【待补：工具进化的实际效果，见修改备注】

本文的贡献如下：

- 把 ACL 2026 的 instruction 学习扩展到工具使用：ontology 的外部知识通过工具按需查询，不再全部写进说明；
- 提出工具和 skill 的自我进化机制，反思可以提议新工具、新步骤，并配有机器检查加审核 agent 的准入机制，保证进化安全、可控；
- 在 UMR 的句子图和文档级关系上验证这一方法：每句只需 3 次调用，效果优于模仿人类流程的方法，成本约为其十分之一；
- 通过逐步消融说明：复杂标注的可迁移提升主要来自 instruction，额外的检查步骤难以迁移到新文档。
